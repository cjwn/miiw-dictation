# 米物语音键 for Windows

米物精英键盘语音键 → 文字。**按住语音键说话，松开后约 0.5 秒文字自动打出来。**

替代搜狗智能助手那一整套：不装驱动、不装输入法，只有一个单文件小程序。

## 为什么不用 `Win+H`

Windows 11 的 `Win+H` 是「语音输入」，中文好用。但 **Windows 10 的 `Win+H` 是「听写」，中文基本不可用**：

- 面板能正常弹出、麦克风电平也在动，但一个字都不出
- 已确认不是键盘问题：把清晰的中文语音**外放给系统 OneCore 引擎**直接识别，返回的也是 `TimeoutExceeded` / 空结果
- 桌面版 SAPI 中文引擎更差（把「一二三四五」识别成「皮尔上市的」，置信度 0.04）
- 在多台 Win10 机器上复现

所以本程序默认**自己做录音 + 调用 ASR 接口**，完全绕开 `Win+H`。想用系统听写仍可以 `--win-h` 切回去。

## 前提

1. 键盘切到 **2.4G 接收器模式**（USB 接收器插在电脑上）。
   - 语音键的私有 HID 报告（`B0 01/03/00`）只存在于接收器的厂商通道（Usage Page `0xFF00` / Usage `1`）；
     蓝牙 BLE 模式下键盘只有标准 HOGP，没有这个通道，也没有音频端点。
2. Windows 10 1809+ / Windows 11。
3. 一个可用的 MiMo 接口（`MIMO_BASE_URL` + `MIMO_API_KEY`）。没有的话可以用 `--win-h` 走系统听写。

## 配置识别接口

在 PowerShell 里设一次即可（用户级，长期有效）：

```powershell
setx MIMO_BASE_URL "https://你的接口地址/v1"
setx MIMO_API_KEY  "你的 key"
```

接口需要是 OpenAI 风格：`POST <base>/chat/completions`，`model=mimo-v2.5-asr`，
消息体里放一个 `input_audio` part。

程序读取顺序：**命令行参数 → 进程环境变量 → 注册表 `HKCU\Environment`**。
也就是说 `setx` 之后不用重开终端，也不用重开程序。

也可以直接传参（适合临时测试）：

```text
MIIW Voice.exe --base-url=https://xxx/v1 --api-key=tp-xxx
```

> key 不要写进仓库。`.gitignore` 已排除 `*.env` / `*.key`。

## 构建

把 `MIIWVoiceWin` 文件夹拷到 Windows 上，**双击 `build.bat`**，会在同目录生成 `MIIW Voice.exe`。

用的是 Windows 自带的 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，不需要 Visual Studio、
不需要 .NET SDK、不需要联网。

## 使用

1. 双击 `MIIW Voice.exe`，托盘出现麦克风图标（没有主窗口）。
2. 把光标放进任意可输入文字的地方。
3. **按住语音键说话，松开结束**，约 0.5 秒后文字自动出现。
4. 右键托盘图标：
   - 「登录时自动运行」写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
   - 「打开日志」看 HID 报告、录音长度、识别结果
   - 「退出」

日志位置：`%LOCALAPPDATA%\MIIWVoice\voice.log`

## 命令行参数

| 参数 | 作用 |
| --- | --- |
| `--win-h` | 退回旧模式：把语音键翻译成系统 `Win+H`，不做应用内识别 |
| `--asr` | 应用内识别（默认） |
| `--system-mic` | 录音用系统默认输入设备，而不是键盘自带麦克风 |
| `--keyboard-mic` | 按键时开键盘自带麦克风（`B2 01` / `B2 00`）。ASR 模式下默认开启 |
| `--no-input` | 只记录日志、不注入按键 |
| `--slow` | 把 Win 组合键拆成几步发送（仅 `--win-h` 模式有效） |
| `--no-toggle` | 松手发 `Esc` 而不是第二次 `Win+H`（仅 `--win-h` 模式有效） |
| `--dump` | 把接收器所有原始 HID 报告写进日志 |
| `--autostart` | 首次运行时直接写入开机启动项 |
| `--base-url=` / `--api-key=` | 临时覆盖接口地址 / 密钥 |

## 隐私

应用内识别会把**每次按住语音键的录音上传到所配置的 MiMo 接口**。录音只在内存里流转，
不落盘、不保存历史。如果介意，请用 `--win-h` 模式（那个模式不录音，音频由系统听写自行处理）。

## 已知限制

- **键盘断电重开后不需要拔插接收器**。实测语音通道本身会自愈；真正出问题的是状态机：
  按着语音键把键盘关掉时，「松开」报告永远不会到，`buttonHeld` 会永久停在按住状态，
  之后所有按键都被忽略（表现为“找不到键盘”），只有拔插接收器重建读循环才能恢复。
  现在有两层兜底：
  1. 接收器在键盘断开/重连时会发一条未文档化的 `01 e3` 链路事件，收到即复位状态机；
  2. 万一状态机已经卡住，再收到一次 `B0 01`（新按下，区别于 `B0 03` 重复帧）也会自动收尾重来。
  另有一层安全网：空闲时每 60 秒静默重发一次握手（录音期间暂停）。
  注意：不能用“静默超时”当判据 —— 空闲时接收器本来就不发任何东西，那样会每 20 秒误报一次。
- **按键提示默认不用系统通知**。托盘图标按状态变色（录音红 / 识别中橙 / 出错深红），
  屏幕底部居中显示一条小浮条（`● 录音中`、`◎ 识别中`、`! 错误原因`）。
  浮条用 `WS_EX_NOACTIVATE` + `SW_SHOWNOACTIVATE` 显示，不会抢焦点；
  识别成功时浮条立刻收起——文字已经打出来了，不需要再额外提示“完成”。
- **单次录音上限 60 秒**（16 kHz / 16-bit / 单声道 = 1.83 MB），到上限会自动收尾上传，不丢弃。
  60 秒同时也是识别接口的**可靠上限**：实测 60 秒音频完整返回 12/12 句，而 120 秒和 300 秒
  都只返回第一句（接口不报错，静默截断）。**不要把这个上限调大。**

- **键盘休眠后接收器会输出全零 PCM**。此时录音全是 0，程序会检测到并在日志里提示
  「请先按一下键盘再试」；按一下键盘即可唤醒无线链路。
- **每次开麦有约 300~400ms 的直流爆音**：采样值从 0 指数型冲到 int16 下限并卡住约 100 个样本。
  程序固定等 450ms 再开始录音来避开它。
- **键盘麦克风电平很低**，而且 Windows 的麦克风音量滑块对这个设备**完全无效**
  （实测 0% 与 100% 录出的波形逐样本一致）。ASR 仍能正确识别，但本地做 VAD 时要注意。
- **前台是管理员权限窗口时 `SendInput` 会被 UIPI 拦掉**（Windows 的规则）。在普通窗口里用没问题。
- 需要联网；接口不可用时会在日志里记录 HTTP 错误并跳过输入。
- 只匹配 VID `0x3044` / PID `0x507c` 的厂商通道，别的键盘不适用。

## 与 macOS 版的对应关系

| 功能 | macOS（`../VoiceKey.c`） | Windows（本目录） |
| --- | --- | --- |
| 匹配厂商通道 | `IOHIDManager` VID/PID/`0xFF00`/`1` | `SetupAPI` + `HidD_GetAttributes` + `HidP_GetCaps` |
| 初始化握手 | `E1/D1/E2/B1` ×2 + 6 秒 `E2` 保活 | 相同 |
| 写输出报告 | `IOHIDDeviceSetReport` | **`WriteFile`**（`HidD_SetOutputReport` 在本设备上返回 TRUE 但不发送） |
| 开关键盘麦克风 | `B2 01` / `B2 00` | 相同 |
| 识别 | 系统听写 / 应用内 Speech | MiMo `mimo-v2.5-asr` |
| 出字 | 听写或粘贴 | `SendInput` + `KEYEVENTF_UNICODE` |
| 界面 | 菜单栏 `NSStatusItem` | 托盘 `NotifyIcon` |
